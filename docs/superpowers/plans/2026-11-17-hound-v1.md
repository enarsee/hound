# hound v1 (phase A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Implementer subagents run on Opus 5.5 (`model: "opus"`), as the user asked. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `hound` binary that indexes Claude Code and pi session files, merges them with live herdr panes, and offers a popup that searches all of it and jumps to or resumes the chosen session.

**Architecture:** A Cargo workspace with two crates. `hound-core` is the common core and knows nothing about herdr or terminal UI: harness adapters turn session files into cleaned messages; a Tantivy index stores them with per-file offsets for incremental refresh; a `Host` trait describes whatever terminal environment hound runs in (list live panes, focus one, open a new one); pure functions merge, rank and decide what Enter does. `hound` is the frontend crate: the ratatui TUI, the command line, and the herdr implementation of `Host`. With no host, the same TUI runs standalone and Enter resumes the session in the current terminal. Other hosts (tmux, others) or other frontends can be added later on top of `hound-core` without changing it. Phase C (`hound serve`) is out of scope, but refresh and enrichment are library calls so it can be added without touching UI or index.

**Tech Stack:** Rust stable, tantivy, ratatui + crossterm, clap, serde/serde_json, toml, a fuzzy matcher crate (nucleo-matcher or equivalent), an flock crate, a blocking HTTP client (ureq or equivalent), tempfile (dev). Exact crates and versions are the implementer's choice; check current docs for each crate's API rather than relying on memory.

**Spec:** `docs/DESIGN.md` — read it before any task.

**Test-first rule:** every task's tests are given below and are the acceptance criteria. Write them first, watch them fail, then implement. Do not weaken or delete a given assertion; if one is wrong against real herdr/harness behaviour, stop and report instead of changing it. Extra tests are welcome.

## Global Constraints

- Session files are read-only: never write, move, lock or truncate anything under `~/.claude` or `~/.pi`.
- Tests never touch `~/.claude`, `~/.pi`, `~/.local/state/hound` or the running herdr session. Adapters and the index take root paths; the host (herdr) is behind a trait.
- No herdr command that creates, closes, focuses or sends input may run in tests or during development against the default session. Manual end-to-end checks use `herdr --session hound-test`.
- The popup never blocks on indexing or the LLM.
- `hound-core` must not depend on ratatui or crossterm, and no file under `crates/hound-core/` may mention herdr (code, comments, identifiers or tests). Everything host-specific lives in `crates/hound/`.
- No network calls except the enrichment endpoint, and only when `enrich.enabled = true`.
- State: `~/.local/state/hound/` (index in `index/`, `state.json`, `writer.lock`). Config: `~/.config/hound/config.toml`. Both overridable by `HOUND_STATE_DIR` / `HOUND_CONFIG`.
- herdr agent names must match `[a-z][a-z0-9_-]{0,31}` and be unique among live agents.
- Timestamps are Unix seconds (`i64`) everywhere inside the crate.
- Commit after every task with a conventional-commit message ending in the `Co-Authored-By` line for the implementing model.

## Review Focus

1. A single multi-megabyte JSONL line (tool output, request blob): parsing must not fail or blow the time budget. → Task 2, `huge_line_is_skipped_cheaply`.
2. Invalid UTF-8 or a truncated final line in a session file: skip, keep the rest, retry the tail next refresh. → Task 2, `invalid_utf8_and_partial_tail`.
3. Query text with characters a query parser treats as syntax (`"`, `:`, `-`, `(`, `*`): must search literally, never error. → Task 5, `punctuation_in_terms_is_literal`.
4. Resume half-fails (tab created, agent start fails): report the error, leave the tab, do not retry or create a second tab. → Task 8, `start_failure_reports_and_does_not_retry`.
5. First run / empty index, and a terminal too small to draw: popup renders an empty state and does not panic. → Task 9, `renders_empty_and_tiny`.

Layout on disk: `<root>/<slug>/<session-uuid>.jsonl` and optional `<root>/<slug>/<session-uuid>/subagents/agent-*.jsonl` (ignore `*.meta.json`).

Record handling (one JSON object per line):

| Record | Result |
|---|---|
| `type:"user"`, `message.content` a string | `User` message |
| `type:"user"`, content array, block `type:"text"` | `User` message per block |
| `type:"user"` with `isMeta:true` | skipped |
| content block `type:"tool_result"` | skipped |
| `type:"assistant"`, block `type:"text"` | `Assistant` message |
| `type:"assistant"`, block `type:"thinking"` | skipped |
| `type:"assistant"`, block `type:"tool_use"` | `Tool` message, text `"<name> <arg>"` where arg is the first present of `input.command`, `input.file_path`, `input.path`, `input.pattern`, truncated to 200 chars; name alone if none |
| `type:"ai-title"` | `title = aiTitle` |
| main file record with `isSidechain:true` | skipped |
| any record in a `subagents/` file | same rules, `subagent: true`, sidechain flag ignored |
| anything else, or a line that is not valid JSON/UTF-8 | skipped |

`cwd` from any record feeds `cwds`; `timestamp` (RFC 3339) feeds `first_ts`/`last_ts`/`Message.ts`. A line longer than 1 MiB is skipped without JSON-parsing it. A final line with no trailing newline is not consumed (`new_offset` stays before it).

### Task 4: Index and incremental refresh

**Files:** Create `crates/hound-core/src/index/mod.rs`, `crates/hound-core/src/index/refresh.rs`, `crates/hound-core/tests/index_refresh.rs`.

**Interfaces — Consumes:** `Adapter`, model. **Produces:**

```rust
#[derive(Clone, Debug, PartialEq)] pub struct FileState { pub path: PathBuf, pub subagent: bool, pub size: u64, pub offset: u64, pub head_hash: u64 }
#[derive(Clone, Debug, PartialEq)] pub struct SessionDoc {
    pub key: SessionKey, pub title: String, pub cwds: Vec<String>, pub resume_cwd: String,
    pub started_at: i64, pub updated_at: i64,
    pub summary: Option<String>, pub category: Option<String>, pub tags: Vec<String>,
    pub files: Vec<FileState>, pub enriched_at_bytes: u64 }
impl SessionDoc { pub fn total_bytes(&self) -> u64; }  // sum of files[].offset
#[derive(Debug, Default, PartialEq)] pub struct RefreshStats { pub added: usize, pub updated: usize, pub removed: usize, pub full_reindex: usize, pub unchanged: usize }
pub struct Index;
impl Index {
    pub fn open(dir: &Path) -> anyhow::Result<Index>;      // creates; wrong/missing schema version or unreadable => wipe and recreate
    pub fn sessions(&self) -> anyhow::Result<Vec<SessionDoc>>;
    pub fn session(&self, key: &SessionKey) -> anyhow::Result<Option<SessionDoc>>;
    pub fn refresh(&self, adapters: &[Box<dyn Adapter>], progress: &mut dyn FnMut(usize, usize)) -> anyhow::Result<Option<RefreshStats>>;
        // None = another process holds writer.lock; nothing done
}
pub const SCHEMA_VERSION: u32 = 1;
```

Rules: `title` = harness title if any, else stored first prompt truncated to 80 chars, else `"(untitled)"`. `resume_cwd` = first cwd recorded in the main file (`""` if none). `started_at`/`updated_at` = min/max timestamp across files; if no timestamps, the main file's mtime. `head_hash` = hash of the first `min(size, 4096)` bytes. Per file on refresh: unchanged size → skip; grown and head hash equal → parse from `offset`, add messages; shrunk or head hash differs → delete all of the session's message docs and reparse every file of that session (`full_reindex += 1`). Sessions no adapter discovers any more are deleted. Enrichment fields survive updates and full reindexes. One commit per refresh. `progress(done, total)` is called once per session. `dir` layout: `index/`, `state.json` `{schema_version, heartbeat}`, `writer.lock` (flock, non-blocking).
